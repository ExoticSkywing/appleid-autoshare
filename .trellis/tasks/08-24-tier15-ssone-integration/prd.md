# Tier-1.5 SSONE 鉴权源接入需求

## Goal

为 Apple ID AutoShare 增加一个可独立降级的 Tier-1.5 鉴权储备源。该来源不是一手上游，而是登录后可访问的服务端聚合页面；仅当无法合理发现其真实上游时，允许以受控 Session 轮询方式接入。项目仍以现有两个 Tier-1 直连源为主，Tier-1.5 不得成为系统可用性的单点依赖。

## 已验证事实

- 目标页面：`https://sky.ssonenetwork.com/docs?platform=ios&article=0`。
- 未携带浏览器 clearance 时返回“浏览器检查”页面；携带有效登录会话后返回完整 SSR HTML。
- 页面文本明确表示其聚合两个平行供应商；页面同时展示“来源更新时间”和“本站同步时间”，因此判定 SSONE 是中间聚合层，而非已证明的一手源。
- 账号数据直接存在于服务端 HTML 的 `[data-sky-shared-account-value]` 节点内，每个账号组具有“可用/正常”状态及来源更新时间。
- 连续刷新会随机返回两个账号组；实测 10 次刷新去重后得到 6 个账号对，说明需要有限多次采样才能覆盖当前轮转集合，但不能假设池大小永久等于 6。
- 前端脚本与 HTML 未暴露真实供应商 URL/API；公网精确账号特征检索没有得到可靠来源命中。继续盲目溯源投入产出比低，因此批准降级接入。
- 当前用户提供的 Cookie 是短期敏感凭据，已在聊天中暴露；不得写入 Git、Trellis 文档、测试夹具、日志或镜像。上线前应撤销/轮换，并通过部署秘密注入新凭据。

## Requirements

### R1 — 可选且隔离的第三来源

- 将该源作为内部别名 `source_c` / Tier-1.5 reserve 接入，不改变现有 `source_a`、`source_b` 的主源地位。
- Tier-1.5 关闭、过期、被封或解析失败时，现有主源轮询、就绪判断及用户出号流程必须继续工作。
- 公共 API、静态资源、前端状态、错误响应及用户可见文案不得出现 SSONE 域名、路径、Cookie 名、内部别名或供应商数量。
- 生产配置必须允许显式启用/禁用该源；默认配置样例中不得包含真实会话值。

### R2 — 凭据与秘密管理

- URL、完整 Cookie header 或等价的 clearance/auth/csrf 值只能通过运行时 secret 注入；禁止命令行参数明文、仓库文件、Docker layer、前端 bundle、日志及异常文本。
- 适配器不得解析或记录 Cookie 子字段；对应用层而言它是一个不透明 secret header。
- 启用 Tier-1.5 时缺少 URL 或凭据必须在启动校验阶段失败；禁用时不得强制要求其配置。
- 凭据失效应归类为通用 `auth_expired`/`challenge_returned` 运维原因码；公共接口仅返回现有通用服务状态。
- 需要形成轮换 Runbook：浏览器重新登录 → 从已授权请求复制 Cookie → 更新 secret → 重启/滚动加载 Worker → 执行脱敏探针 → 撤销旧会话。

### R3 — 网络与响应识别

- 必须复用现有上游网络安全边界：TLS 校验、有限超时、响应大小上限、默认不跟随重定向、固定 User-Agent/Accept、禁止输出原始 URL/响应体。
- 仅接受 `200` 且 Content-Type/主体符合预期账号页面指纹的响应。
- 如响应标题/正文属于“浏览器检查”、登录页、挑战页，或不存在账号容器，必须视为失败，绝不能把挑战页当作成功的空池刷新。
- 非 2xx、重定向、超限响应、无效 UTF-8、认证失效及页面结构漂移均不得延长旧 slice 的 `valid_until`。

### R4 — 严格 DOM 配对与状态过滤

- 每个 `[data-sky-shared-account-group]` 只能在组状态明确为“可用”，且账号项状态明确为“正常”时进入候选池。
- 账号与密码必须在同一个账号项容器内按标签语义配对；不得依赖全页节点偶数/奇数顺序，以防结构漂移导致跨账号错配。
- 用户名必须通过现有邮箱规范校验；密码非空、长度受限；任何健康异常标记命中即剔除。
- 解析并保存“来源更新时间”作为候选记录上游心跳；“本站同步时间”仅作中间站同步观测，不可替代来源更新时间。
- 对缺少来源时间的记录可选择接受，但其 freshness 只能从本次抓取时间计算，并标记内部置信度降低；不得向公共 DTO 暴露该标记。
- 页面出现重复账号时按 username 大小写不敏感去重，保留来源时间更新的一条；同 username 不同密码时按最新来源时间选择，并产生不含账号值的安全告警计数。

### R5 — 有界轮转采样

- 单个轮询周期允许执行有限次采样，以覆盖随机返回的账号组；默认建议 3 次，必须配置最大值且设置请求间短抖动。
- 每轮采样去重合并；不得以“连续没有新账号”为由进行无界循环，也不得根据历史实测值硬编码池大小为 6。
- 任一采样遇到认证/挑战失败，应终止本轮后续采样并报告单一失败事件，避免加剧封禁。
- 部分采样成功时，仅在结果非空且全部成功样本均通过严格解析后替换该源 slice；产品负责人可接受“本轮仅得到轮转子集”，但不接受混入无法证明健康的记录。
- 默认抓取周期建议 5 分钟，须支持运维配置与抖动；不得高频刷新造成对方压力或 WAF 封禁。

### R6 — 独立 freshness 与降级

- `source_c` 使用独立 Redis slice、`fetched_at`、`valid_until` 和诊断 TTL；任何其他来源刷新不得延长它。
- 因页面本身标注来源更新时间，记录是否可服务必须同时满足：本地 slice 未过期，并且来源更新时间没有超过 Tier-1.5 专用最大年龄。
- 建议初始值：轮询 300 秒、slice 可服务窗口不超过 10 分钟、来源时间最大年龄不超过 15 分钟；最终数值由后端同事根据上游实测更新节奏配置，不硬编码。
- 失败时保留旧 slice 仅供诊断 TTL 使用，但请求时超过 `valid_until` 必须排除；绝不“失败后续期”。
- `/readyz` 维持“至少一个主/储备 fresh slice 可服务”的现有语义；另提供仅限内部运维的按别名健康指标，不能公开真实来源标识。

### R7 — 兼容现有质量反馈与单账号披露

- Tier-1.5 账号进入与现有账号相同的聚合、HMAC 公共 ID、去重、排序、反馈排名及单账号披露流程。
- 不因该站宣称“正常”而写死 `shadowrocket_purchased=true`；只有用户反馈或已存在的可信质量机制可提高“已购小火箭”置信度。
- 公共响应仍只包含既有字段，禁止增加 `source`、供应商组、来源时间原文或中间站同步时间。
- 同一会话换号必须继续避免重复展示；账号密码错误、需要二次验证、登录成功但未购买小火箭均进入现有失败反馈与换号流程。

### R8 — 可观测性与告警（无秘密）

- 指标至少覆盖：轮询结果分类、耗时、解析候选数、去重后数量、challenge/auth 失败、结构漂移、来源过旧、连续失败次数、最后成功时间。
- 日志只能使用内部公共别名（例如 `reserve_c`）、原因码、耗时和计数，不得记录 URL、Cookie、邮箱、密码、HTML、重定向 Location 或原始异常字符串。
- 连续认证失败达到阈值时通知运维轮换凭据；结构漂移与认证失效必须区分，避免错误指导用户刷新 Cookie。

## Acceptance Criteria

- [ ] 新增第三来源后，关闭 Tier-1.5 配置时现有双源测试与行为保持不变。
- [ ] 启用但缺少 URL/凭据时生产启动明确失败；禁用时启动成功。
- [ ] 固定 HTML 夹具验证：同卡片正确配对、只接受“可用 + 正常”、解析来源更新时间、剔除异常标记、重复项正确去重。
- [ ] 负向夹具覆盖浏览器检查页、登录页、空账号容器、嵌套/错序节点、跨卡片密码、超长字段、恶意 HTML；全部 fail closed。
- [ ] 采样测试证明请求次数有上限、可聚合随机子集、认证失败立即停止，且不会假设固定池大小。
- [ ] Redis 测试证明 source_c 独立 freshness；刷新 A/B 不会续期 C，C 失败不会续期旧 slice。
- [ ] 公共 API、静态资源、结构化日志和错误体的扫描结果不包含目标域名、路径、Cookie 名、Cookie 值、来源别名或供应商元数据。
- [ ] 使用专门测试凭据/脱敏 fixture 完成端到端测试；真实用户 Cookie 不进入测试产物。
- [ ] 经用户明确授权的 live redacted probe 只输出 HTTP 结果分类、账号计数、来源时间年龄和内容摘要哈希，不输出凭据。
- [ ] 现有 Turnstile → HttpOnly Session → 单次 Ticket → 单账号 reveal/反馈/换号流程适用于 Tier-1.5 账号，无新增绕过接口。
- [ ] Cookie 过期或 WAF challenge 出现时，Tier-1.5 自动退出 fresh pool，主源仍可服务，告警明确指向凭据轮换。
- [ ] 后端同事交付凭据轮换 Runbook、配置项说明、回滚开关及安全审查记录。

## Out of Scope

- 继续通过大规模公网特征搜索盲猜两个真实上游。
- 绕过登录、破解 WAF、自动获取他人会话或自动化登录未获授权账户。
- 将当前聊天中出现的 Cookie 直接投入生产或写入仓库。
- 登录 Apple 账户进行主动有效性验证、处理二次验证码、修改密码或账号资料。
- 把 Tier-1.5 宣传为已证明的一手 Tier-1 来源。

## PM 决策记录

- **来源等级**：Tier-1.5 鉴权储备源，不计入“一手 Tier-1 核心源”数量。
- **接入决策**：批准降级接入；停止低收益盲目溯源。
- **依赖原则**：两个 Tier-1 继续承担主服务，Tier-1.5 只增加池容量与失败兜底。
- **凭据原则**：上线前必须轮换聊天中已暴露的会话。
